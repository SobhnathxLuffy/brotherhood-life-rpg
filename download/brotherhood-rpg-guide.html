Chapter 01
The five screens, in one page
Every screen has one job, and together they run the whole week. You do not need to memorise the rules — the app computes every number server-side, so what you see is always the truth. Use this page as the map; the app itself teaches the details as you tap.
HUD — command centerwatch
Both brothers' Weekly HP, today's XP, streaks, shields and the WATCHING NOW badge, plus the shared co-op Boss with its pixel titan and HP bar. The two trigger lamps beside the boss mean "≥70 XP today"; when both lamps are lit, the boss takes −140 automatically and the screen shakes.
Quests — the daily grindtap + as you do it
Write tomorrow's three quests (study / workout / skill) at night and lock them before 23:30 IST — locked quests are read-only the next day, so goalposts cannot move. Through the day, tap the + buttons to log real progress; every card shows a live XP preview, and Sobhnath also gets the drag-drop JEE JSON import on the study card.
Vault — entertainment bankspend what you earned
Every XP earned becomes guilt-free minutes: 1 XP = 1 min for Sobhnath, 1 XP = 2 min for Umang. Press START WATCHING before gaming or YouTube and the stopwatch drains your bank live — your brother sees it on his phone too. Lockdown days hard-disable spending.
Arena — weekly war roomsnitch · shields · stakes
The PvP tug-of-war bar, the weekly stake (₹50 treat or a 2-day chore) with Sunday countdown, and the Snitch Tribunal: report cheating to steal up to 30 XP. Repeat offenders get lockdown; cheating during lockdown forfeits PvP and heals the boss. Rest Shields and the 18:00 IST Override live here too.
Chamber — punishment hallUmang's PIN only
Sobhnath's debt forecast: every XP short of 100 becomes exact reps — pushups ×1, pullups ×0.5, crunches ×1, squats ×2, with 5 kg / 2.5 kg weights. Midnight locks the ticket. Next morning Sobhnath does the reps while Umang watches and signs the ticket off with his PIN — no PIN, no forgiveness.
Chapter 02
Two phones, one game
All game state lives on the server, never inside a phone. That single fact makes everything simple: the same URL, opened on two different devices, shows the same HP bar, the same vault countdown, and the same combat feed. When Sobhnath logs a workout on his phone, Umang's HUD updates within about four seconds — the app polls the server continuously, and live socket events push the big moments (boss hits, snitches) instantly.
Setup is one step per person. Open the app URL, pick your name on the login screen, enter your four-digit PIN, and you are in. The session sticks for 30 days, so each brother normally logs in exactly once per month. From then on, daily use is just: lock quests at night, tap "+" through the day, press START in the Vault before watching anything.
Install it as an app: on Android Chrome open the URL → menu → Install app; it becomes a full-screen icon like any other game. On desktop (CachyOS), launch a standalone window with brave --app=https://your-url.
Right now, in this preview, the app runs against a local development database — it already behaves exactly like the finished product because everything is already server-side. Chapter 04 walks you through moving it to its permanent home on the internet so both phones can reach it from anywhere.
Chapter 03
Switching users with a PIN
One shared device is fully supported. The amber user-switch button sits in the top-right header, next to Settings — or open Settings ⚙ and tap Switch user. Pick the brother taking the seat, enter his four-digit PIN, and the app swaps sessions instantly: his HUD, his vault, his cards.
The switch is a hard swap, on purpose. Entering Umang's PIN signs Sobhnath out of that device completely — his token is replaced, so his account cannot be browsed without his PIN. Switching back needs Sobhnath's PIN again. Two brothers can share one phone indefinitely without ever seeing each other's business, and on separate devices the feature simply never needs to be touched.
Wrong PIN? The seat stays with the current player and the attempt is logged. After ten failed attempts in ten minutes, login locks for a few minutes — brute-forcing a brother's PIN is not a strategy.

Chapter 04
Go live: Supabase + Vercel in 15 minutes
The app is a Next.js project with all logic in server APIs, so "deploying" means two things: a free Postgres database (Supabase) and a free host (Vercel). No code changes are needed, because the database is just a connection string. Supabase's Mumbai region gives the lowest latency for IST schedules. Everything below runs on free tiers.
1Create the databasesupabase.com
New project → region Mumbai (ap-south-1) → create. Open the project, press Connect in the top bar, and copy both pooler URIs. Keep the password handy — you will paste it twice in step 3.
2Push the codegithub.com
The repo is already live at github.com/SobhnathxLuffy/brotherhood-life-rpg. If you ever edit the app locally, commit and push again — Vercel redeploys automatically on every push to main.
3Import into Vercelvercel.com
Sign in with GitHub → Add New → Project → import the repo. The build works with zero configuration. Before pressing Deploy, open Settings → Environment Variables and add the four values from the table below — then deploy.
4Environment variablespaste exactly
DATABASE_URL = Supabase transaction pooler URI (port 6543) with ?pgbouncer=true&connection_limit=1 appended. DIRECT_URL = session pooler URI (port 5432). AUTH_SECRET and CRON_SECRET = any two long random strings (make them with openssl rand -hex 32 in any terminal). These four are the only credentials the app ever needs.
5Create the tables — once1 minute
On your computer, swap in the production schema and push it to Supabase:
cp prisma/schema.postgres.prisma prisma/schema.prisma DATABASE_URL="<DIRECT_URL>" DIRECT_URL="<DIRECT_URL>" npx prisma db push
Then commit the swapped schema file. Tables are created in the cloud; nothing is lost later because all data lives there.
6Cron + install on phonesoptional polish
Midnight rollovers already run whenever either brother opens the app, so cron is optional. For exact 00:01 IST timing even when the app is closed, add a free cron-job.org job hitting your-app.vercel.app/api/cron every 5 minutes with header x-cron-secret. Then install the PWA on both phones (Chapter 02) and log in once each.
Supabase connected yet? Not in this preview — the preview uses a local SQLite file so you can play instantly with zero setup. "Connecting Supabase" is exactly step 1 + the four variables in step 3. Until then nothing is missing locally.
Chapter 05
Where credentials live — and never live
The architecture already follows the boring-but-correct rule: secrets belong in the platform's secret store, never in code. No password, token, or connection string is written in the repository — the tracked .env.example holds placeholders only, and the real .env is permanently git-ignored. Vercel stores the four production variables encrypted and injects them at runtime; Supabase keeps the database password in its dashboard; the phones hold nothing but a 30-day signed session token.
PINs are protected with the same machinery serious apps use: each PIN is hashed with scrypt and a per-player salt before it touches the database, so even a full database leak cannot reveal a PIN. Sessions are HMAC-signed tokens — flipping a single character invalidates them. The GitHub token used to push this repo lives in your account settings, not in any file, and can be revoked from GitHub at any time without touching the app.
If a secret ever does leak, rotation is a two-minute affair: paste new values for AUTH_SECRET or CRON_SECRET in Vercel (everyone simply logs in again) and reset the database password in Supabase. Nothing in the game data needs to change.

Chapter 06
Quick troubleshooting
Ninety percent of "it stopped working" moments resolve in one refresh, because the app self-heals: it polls every four seconds and re-runs any missed scheduler job the moment somebody opens it. The rest of the time, this table finds the fix fast.
SymptomCause & fix
Back to the login screenThe 30-day session expired or the browser cleared storage. Log in again — data is on the server, nothing is lost.
Brother's screen not updatingHis phone lost the connection; refresh once. Polling resumes automatically.
"Too many attempts"Ten wrong PINs in ten minutes. Wait a few minutes — the lock clears itself.
Deploy shows a database errorCheck the four environment variables letter-by-letter; the port 6543 URL must carry the ?pgbouncer=true suffix.
Tables missing on VercelRun the one-time prisma db push from Chapter 04 step 5.
Clock looks wrongIt never is — the server runs everything in IST regardless of the device clock.
